# Offer OS

**Offer OS 让每一次求职，都有清晰的下一步。**

Offer OS 是为**在校学生**（日常实习、暑期实习、校招等场景）打造的求职工作台。它从求职者真实的时间线和动作出发，**全方位、多维度地复合了求职过程中可能遇到的各类场景**，将分散的功能整合为一套统一、连贯的管理体验，而不是又多装一个孤立的小工具。全流程闭环（发现→搜集→简历→面试→记录→复盘→推进下一次），围绕同一岗位上下文持续协同而非功能堆叠；岗位方向不限，按使用者业务画像自由搜集；数据本地存储，隐私优先。 

围绕「从投递到拿 offer」的完整周期，工作台覆盖了**求职闭环全流程**：
- **时间任务看板**——把笔试、面试、网申截止、复盘等节点汇成可视的日程与热力图，让你始终清楚「接下来最重要的事」；
- **岗位管理与搜集**——用看板 / 表格管理每个机会的进展，并通过公司库与平台入口，在尽可能多的场景里搜集有效岗位信息；
- **简历生成**——多版本管理、JD 解析与匹配度评分，并能基于目标 JD 生成更对口的简历；
- **模拟面试**——把岗位与简历放进同一现场，按轮次和题型开展有针对性的练习；
- **记录与复盘**——面试结束后沉淀逐字稿、结构化建议与个人反思，形成可回看的改进资产。

除此之外，工作台还内置**丰富的工具集**，用于不同场景的便捷适配，例如：一键**同步到飞书文档**（让岗位、日程、简历落在统一数据底座）、**多场景岗位信息搜集**（贴近真实招聘渠道去捞有效机会）、以及**校招官网快速填写的插件工具**（减少重复填表的负担）等。

## 本地运行

推荐使用 Node.js 22.12+ 的 LTS 版本。若使用 Node 20，至少需要 Node.js 20.19+；Node.js 21 不在 Vite 7 支持范围内。

```bash
npm install
npm run dev
```

开发服务器启动后，在终端显示的本地地址打开应用。

## 验证与构建

```bash
npm test
npm run test:e2e
npm run build
```

`npm test` 运行单元与结构测试；`npm run test:e2e` 会在 Chromium 的 1440px、1024px 和 390px 视口中验证登录、岗位持久化和仪表盘同步；`npm run build` 生成 Vite 生产构建。

## GitHub Pages 与兼容性

发布项目页面时，请只部署 `dist/` 目录，不要把原始 `offer-os.html` 当作发布入口。若站点路径是 `https://<user>.github.io/<repository>/`，构建时传入仓库路径：

```bash
VITE_BASE=/<repository>/ npm run build
```

本地已验证 Chromium（桌面 / 手机）与 WebKit（Safari 内核）。Microsoft Edge 未安装在当前机器，发布前请在 Edge 中完成一次登录、添加岗位、刷新保存和备份导出的手工验收。

## 数据与备份

岗位、活动和第一切片的数据存放在当前浏览器的 IndexedDB 中，只存在于这个浏览器配置文件和这台设备。刷新页面不会清除数据；清除站点数据、使用隐私浏览窗口或切换浏览器则会失去这份本地数据。

请定期在应用的本地数据控制区导出备份文件，并将文件存放在你自己的可靠位置。恢复时可选择合并导入，或选择替换导入；替换前先保留一份现有导出文件，以便需要时恢复。

## 登录与安全

当前登录流程是本地演示门禁，不是云端账户、身份服务或跨设备认证。它不会把你的求职数据上传到服务器。

不要把 LLM 服务密钥或任何其他凭据提交到仓库、文档、测试样例或构建产物中。若在本地配置了模型服务，请仅按应用界面的本地保存方式使用，并在共享设备上格外谨慎。

## 当前范围

本切片迁移了岗位、活动、仪表盘和本地备份恢复的核心工作流。日历、简历、模拟面试、复盘、门户和设置中的其余模块仍由遗留实现提供，尚未迁移到新的持久化数据层；它们会继续按迁移前的行为运行，后续迁移将分模块进行。
