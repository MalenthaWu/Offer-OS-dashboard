# Offer OS 本地优先架构设计

日期：2026-08-26

## 1. 目标与边界

把现有单文件原型 `offer-os.html` 改造成可长期使用的独立网页应用，同时保留当前视觉设计和主要交互。第一阶段不建设云端账户、多人共享或实时协作，业务数据只保存在当前浏览器。

本阶段交付目标：

- 岗位、日历、简历、面试、复盘和校招入口可以新增、编辑、删除并在刷新后保留。
- 仪表盘、统计卡片和近三个月热力图从真实岗位及投递记录计算，不再使用固定演示数字。
- 支持本地数据导出、导入和恢复，降低浏览器数据被清理后的丢失风险。
- 保留演示登录入口，但明确标记为本机身份，不提供真实验证码和跨设备同步。
- 代码拆分为边界清晰的原生 JavaScript 模块，为后续接入 Supabase 保留 Repository 接口。

本阶段不包含：真实云端登录、多设备同步、多人协作、服务端 API Key 代理和在线数据库。

## 2. 技术方案

采用以下组合：

- Vite：本地开发、ES Modules 加载、生产构建和 GitHub Pages 发布。
- 原生 HTML、CSS、JavaScript：保留现有界面，不引入 React。
- IndexedDB：保存业务实体和较大的结构化内容。
- localStorage：只保存主题、界面偏好、演示身份和 LLM 本机配置等轻量设置。
- Repository：页面只能通过统一数据接口读写 IndexedDB，不能直接把 DOM 当作数据源。
- App Store：保存当前会话状态并广播实体变化，驱动受影响模块重新渲染。

数据流统一为：

```text
用户操作 → Module Controller → Repository → IndexedDB
                              ↓
                         App Store 事件
                              ↓
             当前模块 + 仪表盘 + 关联模块重新渲染
```

## 4. IndexedDB 数据模型

数据库名为 `offer-os`，初始版本为 `1`。

### jobs

岗位主记录。字段包括 `id`、公司、职位、地点、批次、优先级、阶段、收藏状态、JD、投递方式、链接、备注、创建时间和更新时间。

### activities

岗位过程记录，也是统计和热力图的数据源。字段包括 `id`、`jobId`、类型、发生时间、说明和关联日历事件。类型包括关注、投递、测评、面试、跟进、Offer、拒绝和放弃。

### calendarEvents

用户手动创建或由岗位流程生成的日程。字段包括 `id`、`jobId`、标题、类型、开始时间、提醒信息和完成状态。

### resumes

简历版本。字段包括 `id`、名称、目标岗位、正文结构、技能、来源文件信息、匹配结果、创建时间和更新时间。文件解析后的文本保存在本地，不上传。

### interviewSessions

模拟面试记录。字段包括 `id`、`jobId`、问题列表、回答、计时、反馈和完成时间。

### reviews

复盘记录。沿用现有标题、逐字稿、反思、行动项和建议结构，并补充关联岗位与时间字段。

### portals

校招入口。沿用现有公司、网址、分类、评级、批次、状态、备注和收藏字段。

### meta

保存数据库版本、首次初始化状态、种子数据版本和最近备份时间。

所有实体使用稳定字符串 ID、ISO 8601 时间和显式 `schemaVersion`。Repository 返回普通对象，使未来 Supabase Repository 可以复用同一接口。

## 5. 初始化与旧数据迁移

首次运行按以下顺序初始化：

1. 创建 IndexedDB 和对象仓库。
2. 如果尚未初始化，将现有 HTML 中的演示岗位、日历和简历转换成种子数据。
3. 将 localStorage 中现有的校招入口和复盘记录迁移到 IndexedDB。
4. 校验记录数量和必填字段后写入 `meta.initialized`，避免重复导入。
5. 保留原 localStorage 数据一个版本周期，仅作为迁移回退；确认新数据可读后不再写入旧业务键。

迁移是幂等的：刷新或失败重试不会生成重复记录。任何一步失败都保留原始数据，并在界面提示用户导出诊断信息。

## 6. 模块职责与联动

- 岗位模块是岗位主数据的唯一编辑入口，负责看板、表格、搜索、筛选和拖拽阶段更新。
- 活动记录是仪表盘数字和热力图的唯一统计来源。新增投递或改变阶段时同步生成活动。
- 日历模块查询 `calendarEvents`，岗位面试时间可以生成或更新关联日程。
- 简历模块维护版本，并通过 `jobId` 关联目标岗位和 JD。
- 面试模块保存每次练习，不覆盖历史记录。
- 复盘模块可独立创建，也可以关联岗位或面试记录。
- 官网入口模块独立维护入口数据，不与岗位记录自动合并；用户可以从入口创建岗位。
- 设置模块管理本机身份、偏好、数据导入导出和 LLM 配置。

Store 事件至少包括 `jobs:changed`、`activities:changed`、`calendar:changed`、`resumes:changed`、`interviews:changed`、`reviews:changed` 和 `portals:changed`。模块只订阅确实影响自身的数据事件。

## 7. 错误处理与数据安全

- IndexedDB 不可用、空间不足或事务失败时，取消当前写入并显示可理解的错误，不伪装成保存成功。
- 删除岗位前确认；删除岗位时保留关联活动、日历、面试和复盘，改为解除关联，避免级联误删历史。
- 导入前校验文件格式和 schema 版本；导入采用事务，失败时保持原数据不变。
- 提供完整 JSON 导出，以及导入时的“合并”和“覆盖”两种模式。覆盖操作必须二次确认。
- LLM API Key 不进入 IndexedDB 业务备份，也不提交到 GitHub。独立版继续由浏览器直连时，界面必须提示本机存储和 CORS 风险。
- 所有由用户输入生成的界面文本默认使用 `textContent`；确需 HTML 的简历富文本经过允许列表清理。

## 8. 测试与验收

### 数据层

- 每个 Repository 的新增、读取、更新、删除和索引查询测试。
- 数据库首次初始化、重复初始化和旧 localStorage 迁移测试。
- 备份导出、合并导入、覆盖导入、错误 schema 和事务回滚测试。

### 模块层

- 新增岗位后，看板、列表、仪表盘和统计同步更新。
- 拖拽岗位阶段后，刷新页面仍保持新阶段，并生成正确活动记录。
- 新增投递后，近三个月热力图对应日期和汇总数字更新。
- 日历、简历、面试、复盘和官网入口的完整持久化测试。
- 删除、取消和失败操作不会留下半条记录或错误统计。

### 浏览器验收

- 桌面端 1440px、1024px 和移动端 390px 的关键流程截图对比。
- Chrome、Edge 和 Safari 当前稳定版的 IndexedDB 基本流程验证。
- 生产构建后从静态服务器及 GitHub Pages 子路径加载，刷新和资源地址正常。

## 9. 实施顺序

1. 建立 Vite 原生项目和样式拆分，确保视觉基线不变。
2. 建立 IndexedDB、Repository、Store、迁移和备份能力。
3. 先迁移岗位与活动模块，接通仪表盘和热力图。
4. 迁移日历、简历、面试、复盘和官网入口。
5. 完成设置、导入导出、错误提示和演示身份说明。
6. 执行功能测试、响应式视觉回归和生产构建验证。

每一步都保持应用可运行，并在迁移完成前保留原 `offer-os.html` 作为只读视觉与行为基准。

## 10. 后续云端兼容

第二阶段接入 Supabase 时新增 `SupabaseRepository`，保持与本地 Repository 相同的方法签名。云端身份、行级权限、同步冲突和服务端 LLM 代理作为独立设计处理，不在本阶段预埋复杂同步逻辑。
