# Offer OS 项目介绍页设计

**日期：** 2026-08-27  
**状态：** 已获方案确认，等待规格审阅

## 目标

为 Offer OS 制作一份独立的中文项目介绍 HTML，服务于 WorkBuddy 工作台模板共创大赛投稿、GitHub 项目展示及小红书等社交媒体传播。

页面应让首次接触产品的人在短时间内理解：它服务谁、解决什么问题、包含哪些能力、为何适合复用，以及如何开始使用。页面不虚构线上可用状态或未经验证的成果数据。

## 产品定位

Offer OS 是面向在校学生的全流程求职工作台，适配日常实习、暑期实习、秋招与春招。它把时间任务、岗位搜集与管理、简历生成、模拟面试、面试记录与复盘汇集在一个连贯工作流中，帮助用户持续推进每一个求职机会。

核心主张：**让每一次求职，都有清晰的下一步。**

## 受众与阅读场景

- **大赛评委：** 快速判断模板的适用场景、完成度、可复用性和亮点。
- **GitHub 访客：** 了解项目能力、进入工作台，并掌握基础使用路径。
- **社交媒体读者：** 在移动端短时间内看懂价值，可截取首屏、工作流和模块区作分享素材。

## 信息架构

1. **首屏（产品定位）**
   - 产品名 Offer OS、主标题、简要副标题。
   - 三个场景标签：日常实习、暑期实习、校招。
   - 一个指向现有 `offer-os.html` 的“打开工作台”入口。
   - 以静态产品界面拼贴展示产品感，不依赖外部图片或网络资源。

2. **问题与解法（从分散到闭环）**
   - 概括学生求职中的三类摩擦：机会分散、关键节点易遗漏、准备与复盘相互割裂。
   - 用一段清晰文字说明 Offer OS 将这些信息收敛到一个可推进的工作台。

3. **求职闭环（主叙事）**
   - 以横向流程展示：发现机会 → 收集与管理岗位 → 匹配与生成简历 → 面试准备与模拟 → 记录与复盘 → 推进下一次机会。
   - 强调所有步骤围绕同一岗位上下文协同，而非孤立功能堆叠。

4. **五大模块（功能说明）**
   - 时间与任务看板：集中追踪面试、笔试和截止时间。
   - 岗位管理与搜集：看板管理流程，多渠道收集有效岗位信息。
   - 简历工作区：基于目标岗位 JD 生成、调整和管理简历版本。
   - 模拟面试：结合岗位和简历进行针对性练习。
   - 记录与复盘：沉淀反馈与经验，支持持续改进。

5. **场景适配工具（亮点说明）**
   - 飞书同步：在熟悉的协作环境中同步岗位、日程与简历相关信息。
   - 岗位搜索：围绕目标方向尽可能多场景地搜集有效机会。
   - 校招官网与快速填写工具：减少查找入口及重复填写的操作成本。
   - 此区使用“可扩展工具集”措辞，不承诺所有第三方平台均已完整连接。

6. **三步开始使用（模板复用）**
   - 建立目标：填写个人方向与目标批次。
   - 导入机会：手动添加、同步或通过搜索器收集岗位。
   - 围绕下一步推进：记录节点、准备面试、完成复盘。

7. **收尾与行动入口**
   - 重申“从零散求职信息到有节奏的行动系统”。
   - 保留模板链接、GitHub 链接和社交链接的显式占位，便于投稿前补充。

## 视觉与交互

- 视觉承接现有工作台：深墨色、米白内容区、淡蓝和薄荷绿作为强调色；避免大面积渐变与花哨装饰。
- 单页、响应式布局。宽屏优先提供强节奏的分栏与流程线；移动端改为单列，保证社交传播截图的可读性。
- 使用内联 SVG 图标与 CSS 构建界面示意，避免外部资源失效及版权风险。
- 导航锚点平滑跳转；“打开工作台”链接到项目内现有 `offer-os.html`；其余链接使用清晰占位，不伪造真实地址。
- 首屏、闭环区、模块区应各自形成独立且完整的截图构图。

## 文件与边界

- 新增独立文件：`offer-os-intro.html`。
- 不修改现有 `offer-os.html`，不覆盖用户已有的未提交更改。
- 不接入网络、账号、统计或表单提交能力；本次交付为静态介绍页。

## 验证标准

- HTML 在本地浏览器可直接打开，控制台无脚本错误。
- 视口 390px、1024px 与 1440px 下，页面无横向溢出，正文和关键按钮可读可用。
- 页面清晰包含目标用户、完整闭环、五大模块、工具亮点、三步上手与行动入口。
- 链接到 `offer-os.html` 的路径有效；其他外部链接不会伪装为可用链接。
- 不包含可识别的个人资料、虚构的增长数据或未经证实的集成承诺。
